# ナニスル（旧名: ちかフェス）

現在地の近くで **今日から1ヶ月先まで** に開催されるフェス・イベントを地図で探すPWA。

- 地図は **OpenFreeMap**（OpenStreetMap のベクトル地図。APIキー不要・無料。Googleマップ風の色付きで日本語表記）
- イベントは収集スクリプトが作る **静的JSON** を読むだけ（CORS もAPIキー露出も起きない）
- 地図を引くと大型フェスだけ、寄るほど小さいイベントも現れる

## 使い方

```powershell
npm install
npm run collect   # イベントを集めて public/data/events.json を作る
npm run dev       # http://localhost:5173
```

`npm run dev` は LAN にも公開されるので、同じ Wi-Fi のスマホから
`http://<PCのIPアドレス>:5173` で実機確認できる。

> **現在地の取得には HTTPS か localhost が必要**。
> PCの localhost では動くが、スマホから素の IP アドレスで開くと位置情報がブロックされる。
> 実機で現在地を試すときは、後述のデプロイをして HTTPS で開くこと。

### 公開する

```powershell
npm run build     # dist/ に出力（相対パス出力なのでどこに置いても動く）
```

`dist/` を Netlify / Vercel / GitHub Pages / Cloudflare Pages などに置けば、
HTTPS で配信されて現在地取得も PWA のホーム画面追加も有効になる。

### GitHub Pages にパスワード付きで公開する（いまの本番）

`.github/workflows/deploy.yml` が毎日 03:00 JST に「収集 → ビルド → 暗号化 → Pages へ公開」を行う。
URL は `https://kkoyarad35-dotcom.github.io/fes-map/` で、開くとパスワードを聞かれる。

- GitHub Pages はサーバー側で認証を掛けられないので、**イベントデータ自体を暗号化**して置く。
  `npm run seal` が `dist/data/events.json` を AES-256-GCM（鍵は PBKDF2-SHA256 60万回）で
  `events.bin` に置き換え、平文は消す。復号はブラウザ側の `src/sealed.ts`
- パスワードは Secrets の `SITE_PASSWORD`。変えたら Actions を手動実行すれば反映され、
  各端末に覚えさせた鍵は自動で無効になって入力し直しになる
- リポジトリは公開なので、集めたデータ（`public/data/events.json`）はコミットしない
- 守れるのは**イベントデータ**だけ。アプリの画面と地図は誰でも開ける。
  またパスワードが短い・推測しやすいと、`events.bin` を落として総当たりされうる

手元で確かめる:

```powershell
npm run build; $env:SITE_PASSWORD = "試しのパスワード"; npm run seal; npx vite preview
```

### URLを教えた人だけに配る（以前の方式）

誰でも辿れる場所には置きたくないので、**推測できない1階層（合言葉）の下**に
アプリを置いて、そのURLを直接渡す形にしてある。

```powershell
npm run share           # ビルドして share/ に詰める
npm run share:preview   # 本番と同じヘッダを付けて手元で確認（http://localhost:4173/<合言葉>/）
```

`share/` の中身はこの4つ。**`share/` ごと**デプロイする（`dist/` ではない）。

```
share/
  <合言葉>/      アプリ本体。ここがURLになる
  _headers       ヘッダ設定（Cloudflare Pages / Netlify が読む）
  vercel.json    ヘッダ設定（Vercel が読む）
  robots.txt     検索避け（robots.txt しか見ないbot向けの念押し）
```

> **ヘッダの付け方はホスティングごとに違う。** `_headers` は Cloudflare Pages と
> Netlify の形式で、**Vercel はこれを読まない**。Vercel に `vercel.json` 無しで上げると、
> 検索避けも Referer 遮断も CSP も全部無効のまま公開されてしまう。
> どちらでも効くように、`scripts/lib/share-headers.mjs` の1つの定義から両方書き出している。
>
> `vercel.json` の `trailingSlash: true` も必須。ビルドは相対パス（`base: './'`）で
> 出しているので、`/<合言葉>` とスラッシュ無しで開かれると
> `./assets/…` が `/assets/…` に解決されて404になる。

### デプロイ

```powershell
npm run share

# Vercel
npx vercel login                      # 初回だけ。ブラウザで承認する
npx vercel deploy --prod share        # → https://<プロジェクト名>.vercel.app/<合言葉>/

# Cloudflare Pages
npx wrangler login                    # 初回だけ
npx wrangler pages deploy share       # → https://<プロジェクト名>.pages.dev/<合言葉>/
```

プロジェクト名がドメインの一部になる。合言葉は `data/.share-token` に残るので、
デプロイし直しても **一度配ったURLは生き続ける**。

配るURLは **末尾のスラッシュまで含めた** `https://<ドメイン>/<合言葉>/`。
ドメイン直下は 404 になるので、合言葉を知らない人には入口が無い。

合言葉は `data/.share-token` に残る（gitignore 済み）。作り直さなければ
何度デプロイしてもURLは変わらないので、配った人はそのまま使い続けられる。
**漏れたとき**は作り直せば前のURLが死ぬ。

```powershell
npm run share -- --new  # 合言葉を作り直す。前のURLを渡した人は開けなくなる
$env:SHARE_TOKEN = "..."  # 合言葉を自分で決めたいとき
```

#### ここまでで防げること / 防げないこと

| | |
| --- | --- |
| 受け取った人が中身を書き換える | **防げる。** 静的配信で書き込み口が無く、投稿機能も無い。イベントの更新は手元の `npm run collect` → デプロイだけ |
| 配信物を途中で差し替えられる | **防げる。** HTTPS + CSP `default-src 'none'`。外部スクリプトもCDNも使っていないので、注入できる隙が無い |
| 検索から見つかる | **防げる。** `X-Robots-Tag: noindex` と `robots.txt` |
| 公式サイトを踏んだ先に共有URLが漏れる | **防げる。** `Referrer-Policy: no-referrer` と、外部リンクの `rel="noreferrer"` |
| 他サイトに埋め込まれて自分のもののように見せられる | **防げる。** `X-Frame-Options: DENY` と CSP `frame-ancestors 'none'` |
| **渡した人がURLを他人に転送する** | **防げない。** 合言葉URLは「知っていれば誰でも入れる」鍵で、人数を絞る仕組みではない。本当に人を限定するなら Cloudflare Access のメール許可リストや Basic 認証など、認証を足すことになる |
| **中身をコピーして別のサイトに置かれる** | **防げない。** ブラウザに配った時点で相手の手元にある。静的サイトで技術的に止める手は無い |

`_headers` は `scripts/lib/share-headers.mjs` が生成している。ヘッダを直すときは
`share/_headers` ではなくそちらを直す（`npm run share` で上書きされる）。
確認サーバーも同じ定義を読むので、**手元で通れば本番でも通る**。

> データソースの利用条件に注意。`walkerplus` / `kokuchpro` は
> 「個人が非商用で使う」前提で入れてある（後述）。身内にURLを渡す範囲を超えて
> 広く配るなら、そのソースを外すか規約を確認すること。

## データはどこから来るか

`scripts/sources/` の各モジュールが収集を担当し、`scripts/build-events.mjs` が
それらをまとめて `public/data/events.json` に書き出す。

| ソース | 状態 | 内容 | 備考 |
| --- | --- | --- | --- |
| `manual` | **すぐ使える** | `data/my-events.json` に自分で書いたイベント | 確実に載せたいものはここ |
| `walkerplus` | **すぐ使える** | ウォーカープラスの全国イベント一覧 | 件数の主力。**個人・非商用の前提**（後述） |
| `kokuchpro` | **すぐ使える** | こくちーずプロの個人・団体主催イベント | 座標と時刻が入っている。**同上** |
| `opendata` | **すぐ使える** | 自治体オープンデータの「イベント一覧」CSV | 申請不要・無料。地域行事／講座が中心 |
| `sample` | **すぐ使える** | `data/sample-events.json`（**実在しません**） | 動作確認用。不要なら中身を `[]` にする |
| `connpass` | APIキー申請が要る | IT系の勉強会・カンファレンス | 食フェスは含まれない |

### ウォーカープラス（`walkerplus`）— 個人・非商用の前提

全国のイベント一覧ページに埋め込まれている **schema.org/Event の JSON-LD** を読む。
HTMLの構造ではなく構造化データを見ているので、デザイン変更では壊れにくい。
`name` / `startDate` / `endDate` / `location` / `description` / **`url`（公式サイト）** / `image` が取れる。

**取得の作法**（2026-09-04 時点の `robots.txt` を確認して決めた）:

- `/event_list/` は `Disallow` に入っていない（禁止は `/release*`・`/press*` など）
- robots.txt に `User-agent: ClaudeBot` / `Crawl-delay: 3` の指定があるため、**3秒以上の間隔**を厳守する
- 一度読んだページは `data/.cache/` に12時間キャッシュし、再実行では取りに行かない

> **robots.txt は利用規約とは別物**で、規約側が自動取得を制限していることがある。
> このソースは「個人が非商用で使う」前提で入れてある。
> **公開・再配布・商用利用をするなら、このソースを外すか、規約を確認して判断すること。**

読む範囲は環境変数で調整できる（1ページ10件、都道府県は自動検出）。
1ページ目に出ている掲載総数から必要なページ数を割り出すので、
上限を大きくしても空ページは叩かない。

```powershell
$env:WP_PAGES = "20"          # 都道府県ごとの「全ジャンル」ページ数の上限（既定6）
$env:WP_FOOD_PAGES = "8"      # 加えて読む「グルメ・フードフェス」ページ数（既定3）
$env:WP_TOKYO_PAGES = "130"   # 東京都だけの上限（既定130）
$env:WP_NAGANO_PAGES = "40"   # 長野県だけの上限（既定40）
```

全国を一律に深掘りすると数千リクエストになるので、`FOCUS_PAGES` に書いた
都道府県だけ厚く読む作りにしてある。他県を厚くしたいときはここに足す
（都道府県コードは `/event_list/ar0313/` の `ar0313` の部分）。

初回は Crawl-delay 3秒ぶん時間がかかる。2回目以降はキャッシュから読むので、
増やしたページだけ取りに行く。

### こくちーずプロ（`kokuchpro`）— 個人・非商用の前提

個人・団体が主催する小さな催しが載っていて、ウォーカープラスの穴を埋める。
JSON-LD に **緯度経度と開始時刻がそのまま入っている**のが強みで、
ジオコーディングが不要なうえ、開催時間を「終日」ではなく実時刻で出せる。

- robots.txt の Disallow は `/api/` `/entry/` `/mypage/` など。一覧の `/s/` は対象外
- `*` に Crawl-delay の指定は無いが、他のbot向けに2〜30秒を指定しているので2.2秒空ける
- オフライン開催（`et-0`）に限定。オンラインは地図に出しても意味がない
- **ビジネス系ジャンル（人脈／交流会、営業、経営など）は読まない。**
  それでも紛れ込む「カフェ会」「名刺交換」の類はタイトルで除外している

```powershell
$env:KP_PAGES = "3"   # 1日・1ジャンルあたりのページ数上限（既定3、1ページ約40件）
```

**座標の精度**: JSON-LD の住所は都道府県＋市区町村までしか無い。会場名を足して
国土地理院APIで引き、当たらなければ市区町村の代表点に落とす。後者は `approx: true` を立て、
UI側で「約○km」「位置は市区町村のおおよその場所」と断る。

### 自治体オープンデータ（`opendata`）

国の推奨データセットに「イベント一覧」が含まれているおかげで、多くの自治体が
ほぼ同じ列構成のCSVを公開している。それを CKAN のAPIで探して読んでいる。

| カタログ | ベースURL |
| --- | --- |
| 東京都オープンデータカタログ | `https://catalog.data.metro.tokyo.lg.jp` |
| BODIK ODCS（九州中心に全国） | `https://data.bodik.jp` |
| 横浜市オープンデータ | `https://data.city.yokohama.lg.jp` |
| オープンデータプラットフォーム（jig.jp） | `https://ckan.odp.jig.jp` |

`CATALOGS` に足せばカタログを増やせる。CKAN であれば
`<base>/api/3/action/package_search?q=イベント` が通るかどうかで判断できる。

**取得の作法**（`scripts/lib/httpcache.mjs`）:

- 一度落としたCSVは `data/.cache/` に12時間キャッシュし、再実行では取りに行かない
- 同じホストへは 700ms 以上の間隔を空ける
- 1データセットにつきCSVは新しいものから2本まで（年度別ファイルが数十本ぶら下がっていることがある）
- 403 / 429 / 503 を返したホストは、その実行中は以降アクセスしない

> 開発中に、1データセットのCSVを全部落とす実装で BODIK から 403 を受けた。
> 上記の制限はその対策なので、緩めるときは相手が自治体のサーバーであることを踏まえて判断すること。

**データの質について**、そのまま入れると地図が使い物にならないので次を落としている:

- 「受講生募集」「パブリックコメント」など、催し物ではないお知らせ（`NOT_AN_EVENT`）
- 開催期間が45日を超えるもの — 実体は年度通期の定例行事（「第3水曜日」など）や募集期間
- 開催期間が10日を超えるものは `scale` を下げ、地図を拡大したときだけ出るようにする
- 緯度経度が無く、住所からも特定できなかった行

### connpass を有効にする

1. <https://help.connpass.com/api/> の利用申請フォームから申請する（数日で承認）
2. 届いたキーを環境変数に入れる

```powershell
$env:CONNPASS_API_KEY = "取得したキー"
npm run collect
```

キーが未設定なら、このソースは黙ってスキップされる。

### 食フェスを増やすには

`connpass` はIT勉強会しか持っていないので、**食フェスの網羅性はここでは埋まらない**。
現実的な選択肢は3つ:

1. **`data/my-events.json` に手で書く** — 今すぐできる。`lat`/`lon` を省略すれば
   `address` から国土地理院APIで自動的に緯度経度を補完する。
2. **[イベントバンクAPI](https://api.eventbank.jp/) を契約する** — 地域イベント・食フェスの
   国内最大級の供給元。有料・要契約。契約後は `scripts/sources/eventbank.mjs` を
   `connpass.mjs` と同じ形で書き、`build-events.mjs` の `SOURCES` に足すだけでよい。
3. **自治体オープンデータを足す** — 東京都オープンデータAPIカタログなど。
   自治体ごとに形式が違うので、対象を絞って個別にアダプタを書くことになる。

### 新しいソースを足す書き方

`scripts/sources/` にモジュールを1つ作り、次の4つを公開する。

```js
export const id = 'eventbank';
export const label = 'イベントバンク';
export const url = 'https://api.eventbank.jp/';

/** @returns {Promise<EventItem[]>} src/types.ts の EventItem 配列 */
export async function collect({ dayKeys, rangeStart, rangeEnd }) { /* ... */ }
```

`scripts/lib/normalize.mjs` の `validate()` を通してから返すと、
必須項目の欠けた行が自動で落ちる。あとは `build-events.mjs` の `SOURCES` に
import して並べれば、UI側は何も変えずに反映される。

### 手動登録の書き方

`data/my-events.json` は次の形の配列。

```json
{
  "title": "○○フードフェス2026",
  "category": "food",
  "date": "2026-10-04",
  "endDate": "2026-10-06",
  "startTime": "10:00",
  "endTime": "20:00",
  "venue": "○○公園 芝生広場",
  "address": "東京都渋谷区代々木神園町2-1",
  "url": "https://example.com/",
  "price": "入場無料",
  "organizer": "○○実行委員会",
  "scale": 70
}
```

- `category`: 収集時の値（`food` / `music` / `festival` / `art` / `sports` / `market` / `tech` / `other`）は仮のもの。
  - 画面では読み込み時に `src/classify.ts` がタイトルから決め直す。並びは
    グルメ → エンタメ → 祭り・花火 → レジャー → 音楽 → アート → マルシェ → 教室・講座 → その他。
  - 上の6つには多くの人が休日に行きたくなる催しだけを入れる。教室・講座（オカリナ教室・ピラティス教室など）は中身に関係なく「教室・講座」。
  - グルメは「肉フェス」「餃子祭」のように食べ物が主役の催しだけ（ビアガーデンはレジャー、ビュッフェ・アフタヌーンティーはその他）。
  （省略するとタイトルから推定する）
- `lat` / `lon`: 省略可。無ければ `address` からジオコーディングする
- `startTime` を省略すると「終日」扱いになる
- `date` の代わりに `dayOffset`（今日からの日数）でも書ける。サンプルデータが
  日付切れにならないようにこちらを使っている
- **`scale`（0〜100）が、どのズームで地図に現れるかを決める**

### 地図の表示ルール

**段は2つだけ。** 境目は `src/map.ts` の `PIN_ZOOM = 9`。

| ズーム | 出るもの | 丸の位置 | 押すと |
| --- | --- | --- | --- |
| 9未満（引いた状態） | **都道府県ごと**の数字丸（「東京都 42件」） | **地図上のその県の位置**（`src/pref-centers.ts`） | 1件ずつに分かれるズームまで拡大 |
| 9以上（寄った状態） | イベント **1件ずつ**のピン | **そのイベントの座標そのもの** | 詳細を開く |

以前は「画面上46px四方のグリッドでまとめる」中間段があったが、これを捨てた。理由は3つで、
どれもグリッドという作りから直接出てくる:

- 押して寄っても、寄った先で同じグリッドに入り直すので **いつまでも分かれない**。
  `fitBounds` は `maxZoom: 17` で止まるうえ、数十m差の2件は z17 でも同じ46pxに入る
- 丸が **中身の重心** に立つ。重心はイベントが1件も無い場所（海の上、山の中）になる
- ズームのどこにいるかで丸の意味が変わるので、数字が何を数えているのか読めない

いまは「引いたら都道府県、寄ったら1件」だけなので、丸の数字は必ず
**都道府県の件数**を意味し、ピンは必ず**実際の開催地**に立つ。

- **丸はイベントの座標そのものに乗る。** ピンは「丸」だけを箱にして、名前は絶対配置で
  箱の外に出している。名前が有っても無くても丸の中心が座標に一致する
  （名前を含む横長のボタンを `anchor: 'bottom'` で置くと、名前のぶん丸が左にずれる）
- **まとめるのは座標が完全に一致するものだけ。** 同じ会場で複数開かれている場合は、
  いくらズームしても離れないので重ねるしかない。丸の位置は会場のままにして、
  肩に `+2` のバッジを出す。押すと下部シートに中身の一覧が出る
- **都道府県は `address` の先頭から取る**（`src/pref.ts`）。events.json に県の
  フィールドは無い。取れない76件（住所が無い／「日本」だけ）は、**いちばん近い
  「県が分かっているイベント」に合わせる**
- **県の丸の位置は `src/pref-centers.ts` の表**。県の形から「いちばん大きい島の中で境界から
  いちばん遠い点」を求めたもので、`node scripts/build-pref-centers.mjs` で作り直せる。
  以前はイベントの重心近くに置いていたが、イベントが偏っていると隣の県の上に乗って見えた
- **県の丸は県の枠からはみ出さない大きさ。** 同じ表に「その点から県境までの距離（km）」
  も持っていて、今のズームでのピクセルに直した値を丸の半径の上限にする（ズーム中も追従）。
  16px未満では数字を、枠に収まらないときは県名を消す。押せなくなるので8pxより小さくはせず、
  沖縄・東京はズーム5.5未満だと点がわずかに枠を越える
- **マーカーの CSS で `position` は書かない。** `.maplibregl-marker` の `position: absolute`
  を `relative` で上書きすると、マーカーが縦に積まれて2個目以降が下にずれる（実際に起きた）
- **`fitBounds` には「最低このズームまで寄る」が無い。** 県の丸を押して必ず
  1件ずつに分かれるのは、`cameraForBounds` でズームを自分で出して底上げしているから
  （`fitTo` の `minZoom`）。底上げするときは範囲の中心ではなく押した丸の位置に寄る
  —— 東京都のように離島まで含む県だと、範囲の中心が太平洋の上になる
- **マーカーの CSS で `transform` は使えない。** MapLibre が位置合わせのために
  マーカー要素の `transform` をインラインで上書きするので、`scale()` は消えるか座標がずれる。
  大きさで強調したいときは幅と高さを変える（`.pin--selected`）
- **ピンの名前** はズーム12.5以上で出す。ただし先に置いたピンと重なる場合は
  名前を落としてアイコンだけにするので、**ラベル同士は重ならない**
- **`scale`** は表示するかどうかではなく、**重なったときにどちらが名前を出すか**と
  **上限に当たったときにどちらを残すか**の優先度として使う
- 画面上部のバッジに「この範囲に◯件（◯都道府県）押すと拡大」／「この範囲に◯件（◯か所）」を出す
- 1日に出るのは最大333件（開始日ベース）なので、1件1ピンでもDOMマーカーは
  `MAX_MARKERS = 600` に収まる

### 下地の地図を変える

下地は OpenFreeMap の「Liberty」スタイル（タイムズカーシェアやGoogleマップのような色付き地図）。
`scripts/build-map-style.mjs` が取ってきて次のように直し、`src/map-style.json` として同梱している:

- 地名を「Tokyo 東京」の2段から `name:ja` 優先の1段にする
- OSM の都道府県名（`label_state`）を消す。県名はこちらの数字丸が出すので、
  別の位置に県名が出ると丸とずれて見える

別のスタイルにするときは `SOURCE` を変えて `node scripts/build-map-style.mjs` を実行する
（OpenFreeMap なら `bright` / `positron` もある）。配信元を変えたら
`scripts/lib/share-headers.mjs` の `TILE_ORIGIN` と `index.html` の preconnect も直すこと。

## 起動の順番（体感速度のほぼ全部）

**地図を最初に作る。** イベントJSON（gzip 1.4MB・4,979件）と現在地は、届いた順に後から流し込む。

以前は `Promise.all([loadBundle(), getCurrentPosition()])` を待ってから地図を作っていたため、
**現在地の許可ダイアログに答えるまで地図が1枚も出なかった**（`getCurrentPosition` の
タイムアウトは8秒。ユーザーが放置すればそれ以上）。順番を変えただけで、
地図はJSONも位置情報も待たずに出る。

- 起動オーバーレイは**タイルが出た時点**で外す（`map.once('load')`）。
  イベントの読み込み中はシートと上部バッジが「読み込んでいます」を出す
- 現在地が届いたら寄り直すが、**ユーザーが先に地図を動かしていたら視点を奪わない**
- `index.html` でタイル配信元に `preconnect` してTLS握手を先に済ませる
- `moveend` と `zoomend` は1操作で両方飛んでくるので、描画は次のフレームまでまとめる

> まだ重いのは events.json が1か月分・全国4,979件を丸ごと読んでいるところ。
> 詰めるなら日別かメッシュ別にファイルを割るのが次の一手。

## 構成

```
src/
  main.ts            起動と状態管理（絞り込み → 地図 + 一覧の更新）
  map.ts             MapLibre、ピンとまとめピン、ズーム別の表示制御
  date.ts            日本時間での日付処理。複数日開催の判定もここ
  data.ts            events.json の読み込みと入口での検証
  geo.ts             現在地取得と距離計算
  types.ts           EventItem 型とカテゴリ定義
  ui/                日付ストリップ / カテゴリチップ / 下部シート / 描画
scripts/
  build-events.mjs   収集の入口
  sources/           データソースごとのアダプタ
  lib/               ジオコーディングと正規化
data/
  my-events.json     自分で書くイベント

```
